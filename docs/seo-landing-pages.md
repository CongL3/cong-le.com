# App landing pages and sharing kit

Every live app gets a permanent, indexable landing page at
`https://www.cong-le.com/apps/<slug>/`. These pages are generated from the
synced App Store catalogue and use the real product screenshots. They are the
canonical destination for search, social, and community references; store
buttons carry free attribution while the page URL stays permanent.

The crawlable portfolio hub at `https://www.cong-le.com/apps/` is generated from
the same landing pages. It is a discovery and navigation page, not a second
canonical page for any app. New active apps appear there automatically once
their individual landing page passes the normal checks.

## Before adding an app

- Confirm the App Store listing is live and the listing ID is correct.
- Sync the app catalogue and generate its landing page.
- Confirm the app appears in `/apps/` after the catalogue build.
- Check the page copy against the current product and store listing. Remove
  claims that cannot be evidenced.
- Confirm every screenshot is a real current product image and has useful alt
  text.
- Confirm the page has a unique title, description, H1, canonical, Open Graph
  image, Twitter card, structured data, and sitemap entry.
- Add a Google Play destination only after the package has been verified. A
  missing platform listing is better than a guessed link.
- Run `npm run links:check`, `npm run build`, and the Playwright site tests.

## Media kit

`/press/` is a selective sharing page for the apps most suitable for editorial,
creator, directory, and community references. It is generated by
`scripts/generate-press-page.mjs` from the existing public landing pages.

When an app is ready to be included, add its slug to `PRESS_APP_SLUGS` in that
script, add a concise summary only when the landing-page description is weak,
then regenerate and run the normal website checks. Do not add retired apps,
placeholder images, unsupported ratings/download claims, or a store URL copied
from an unverified source.

The media kit uses:

- App Store Connect campaign tokens `congle-web-press-<slug>` with `pt=19678800`.
- Google Play UTM parameters `utm_source=congle`,
  `utm_medium=referral`, `utm_campaign=press_kit`, and the app slug as content.

These links are for measurement, not ranking promises. Review Cloudflare,
Search Console, and store analytics together; privacy-suppressed or missing
campaign rows remain unknown rather than zero.

## New-app handoff

Add the landing-page URL and media-kit decision to the app launch checklist.
The page can launch with the iPhone listing and gain an Android button later
when the Play listing is verified. Keep the URL stable if the app name or store
metadata changes.
