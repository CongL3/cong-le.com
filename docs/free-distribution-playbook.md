# Free app distribution playbook

This is the manual follow-on to the website acquisition work. It is designed
for legitimate directory listings, creator references, and helpful community
answers. It does not automate posting, create duplicate thin pages, or buy
links.

## Use these owned assets

- Portfolio: `https://www.cong-le.com/`
- Press/media kit: `https://www.cong-le.com/press/`
- Permanent app pages: use the relevant Pocket Grove or cong-le.com page
  listed below.
- Store buttons: use the press kit or the store link already present in the
  GitHub README so campaign attribution stays consistent.

## Channel checklist

1. Keep the GitHub README and the press kit current. These are already live.
2. Add only relevant products to free directory or maker profiles such as
   Product Hunt, AlternativeTo, or Indie Hackers. Use the permanent app page
   as the destination and write a description specific to that directory's
   audience.
3. In Reddit, forums, or Q&A sites, answer the question first. Disclose that
   you made the app and include a link only when it genuinely helps answer the
   question. Never copy the same promotional reply across threads.
4. For short-form posts, show a real product flow or useful tip, then link to
   the relevant app page. One product and one user problem per post is enough.
5. Record each placement in the SEO task log with its date, URL, source, app,
   and whether it generated a store visit or install. Treat missing or
   privacy-suppressed attribution as unknown, not zero.

## Free measurement links

For an external source, add tracking to the permanent page link rather than
changing its canonical URL. For example:

```text
https://pocketgrove.com/anniversary-tracker/?utm_source=reddit&utm_medium=referral&utm_campaign=community&utm_content=anniversary-tracker
https://www.cong-le.com/press/?utm_source=product_hunt&utm_medium=referral&utm_campaign=directory&utm_content=ollama-connect
```

The press kit's store buttons already use deterministic App Store Connect and
Google Play campaign parameters. Do not invent a second parameter scheme or
replace a permanent page with a raw store URL when the page adds useful context.

## Guardrails

- No paid placements, link packages, mass account creation, or automated
  community posting.
- No keyword stuffing, competitor trademark bait, or claims such as “best” or
  “#1” without evidence.
- Do not promote retired or unavailable apps, including DocScanner.
- Do not submit a directory listing until the store destination and screenshots
  have been checked against the current public landing page.
- Review Search Console and store reports after enough time has passed; do not
  rewrite an app or infer success from a single click.
